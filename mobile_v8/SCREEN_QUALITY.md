# Adaptive Screen Sharing for Weak Connections (v8)

## Проблема 🔴
При трансляции экрана на слабом интернете изображение зависает и не обновляется. Пользователь не видит изменений на экране удаленного человека.

## Решение ✅
Добавлена адаптивная система качества трансляции экрана с автоматической подстройкой под скорость соединения.

---

## Функции

### 1. **Селектор качества экрана** 
Кнопка "Screen" в строке действий → выбор качества:
- **Ultra** — 1920×1080, 30 fps, 5 Mbps (хорошее соединение)
- **High** — 1280×720, 30 fps, 2.5 Mbps  
- **Medium** — 960×540, 24 fps, 1.5 Mbps (по умолчанию)
- **Low** — 640×360, 15 fps, 0.8 Mbps (слабое соединение)
- **Auto** — автоматическая подстройка

### 2. **Автоматическая адаптация** (режим Auto)
Система мониторит качество соединения каждые 2 секунды:
- **RTT (Round-Trip Time)** — задержка пакета туда-обратно
- **Packet Loss** — потеря пакетов

**Пороги адаптации:**
| Условие | Качество | Описание |
|---------|----------|---------|
| RTT < 80ms, потерь 0 | **Ultra** | Отличное соединение |
| RTT < 150ms, потерь < 2 | **High** | Хорошее соединение |
| RTT < 300ms, потерь < 5 | **Medium** | Среднее соединение |
| RTT > 300ms или потерь > 5 | **Low** | Слабое соединение |

### 3. **Индикатор качества соединения**
Цветная точка рядом с селектором качества:
- 🟢 **Зелёный** — RTT < 80ms (отличное)
- 🟡 **Жёлтый** — RTT 80-150ms (хорошее)
- 🔴 **Красный** — RTT > 150ms (слабое)

Пульсирует быстрее при плохом соединении.

### 4. **Кнопка Sync** (↻)
При нажатии принудительно передаёт текущий кадр экрана:
- Активна только во время трансляции экрана
- Полезна, если изображение "зависло" на стороне собеседника
- Нажимайте несколько раз для переправки кадра

---

## Как это работает?

### При нормальном интернете (RTT < 80ms)
1. Экран отправляется с максимальным качеством (Ultra)
2. 30 кадров в секунду, высокое разрешение
3. Изображение гладкое и чёткое

### При слабом интернете (RTT > 150ms)
1. Система автоматически снижает качество
2. Разрешение уменьшается до 960×540 или 640×360
3. FPS снижается до 15-24 кадров в секунду
4. Более частые кадры благодаря меньшему размеру = меньше зависаний

### При очень слабом интернете (RTT > 300ms)
1. Переключается на режим Low (640×360, 15 fps, 0.8 Mbps)
2. Минимальный размер = минимальная задержка
3. Может потребоваться нажимать Sync для обновления кадра

## Статистика соединения

В консоли браузера (F12 → Console):
```javascript
connectionStats = {
  rtt: 45,           // Задержка в ms
  packetsLost: 0,    // Потеряно пакетов
  jitter: 2,         // Нестабильность в ms
  lastUpdate: 1633024800000  // Время последнего обновления
}
```

## Примеры использования

### Сценарий 1: Трансляция экрана дома (WiFi)
1. Нажми "Screen" → выбери "Auto"
2. Индикатор зелёный → система сама оптимизирует
3. Если заметишь задержку → нажми "↻ Sync"

### Сценарий 2: Трансляция в поезде (слабый 4G)
1. Нажми "Screen" → выбери "Low" вручную
2. Или выбери "Auto" и система упадёт на Low сама
3. Изображение может быть меньше, но не будет зависать

### Сценарий 3: Кадр "зависнул"
1. Нажми кнопку "↻ Sync"
2. Принудительно передастся текущий кадр
3. Если помогло — нажми снова

## Технические детали

### WebRTC API
- `peerConnection.getStats()` — получение статистики соединения
- `sender.setParameters()` — изменение битрейта и FPS на лету
- `displayMedia` — захват экрана с параметрами

### Мониторинг каждые 2 секунды
```javascript
setInterval(updateConnectionStats, 2000)
```

### Сохранение в LocalStorage
- `vc_screenQuality` — выбранное качество (Ultra/High/Medium/Low/auto)

## Совместимость

✅ **Работает:**
- Chrome 83+
- Firefox 66+
- Safari 13+
- Edge 83+
- Мобильные браузеры (где поддерживается getDisplayMedia)

⚠️ **Ограничения:**
- Desktop only (getDisplayMedia недоступен на мобильных системах)
- Требует HTTPS для getDisplayMedia
- Требует пользовательского разрешения на захват экрана

---

## Советы по оптимизации

1. **Закрой браузеры и приложения** при трансляции — снизит нагрузку на сеть
2. **Используй проводное соединение** вместо WiFi для стабильности
3. **Выбери минимальное нужное качество** — Ultra не всегда нужен
4. **Проверь синхронизацию часов** между устройствами
5. **Нажми Sync** если заметишь рассинхронизацию
